Why did the three controlled failed authentication attempts (SOC004-Test01/02/03, 22:29:54/22:30:13/22:30:16) not appear as 4625/4776/4771 events on DC1?

5. Authentication path
The failed attempts used New-PSDrive to \\SOC002-DC1\SYSVOL with an incorrect password. The client received "The specified network password is not correct", indicating the SMB session was rejected. The attempts likely used NTLM (SMB), not Kerberos (no TGT requested). The password validation failure (Credential Validation) is audited as Success only, so 4776 failure events were not generated by policy. Although Logon auditing includes Failure, the failed SMB authentication did not produce 4625 events in the observed windows on either DC1 or WS001.

6. Why 4625/4776/4771 are absent
- 4776 (Credential Validation) failures are not audited because Credential Validation is set to Success only.
- 4771 (Kerberos pre-auth failure) is absent because the failed attempts did not use Kerberos (no TGT request; NTLM/SMB path).
- 4625 (Logon failure) is absent from observed windows on both DC1 and WS001; the reason cannot be conclusively determined from the available evidence. Possible explanations include: the SMB authentication failure occurred before a full logon was attempted/recorded, or the event was not captured in the queried window. This is NOT VERIFIED.

7. What is verified
- Three failed attempts occurred on WS001 at 22:29:54, 22:30:13, 22:30:16 (client output).
- No 4625/4776/4771 events for Test accounts appeared in DC1 or WS001 queried windows.
- Credential Validation auditing is Success-only, explaining absent 4776 failures.
- No Kerberos TGT was requested for the failed attempts (no 4768 for Test accounts).
- ANONYMOUS LOGON 4624 events from 192.168.56.102 were observed.

8. What is not verified
- Whether 4625 events were generated but outside the queried windows.
- Whether the ANONYMOUS LOGON 4624 events correspond one-to-one to the three failed attempts.
- Whether WS001 recorded the failures in other logs not queried.
- The exact LSA/SMB failure path.

9. Telemetry limitations
- Credential Validation audited as Success only suppresses 4776 failure records.
- Kerberos Authentication Service audited as Success only suppresses 4771 records.
- Only 24h+ baseline; limited host diversity.
- WS001 local logs only partially inspected.

10. Impact on detection engineering
Candidate detection conditions cannot rely on 4625/4776/4771 for this specific NTLM/SMB failure path unless audit policy is changed (not done). Detection may need to rely on ANONYMOUS LOGON 4624 patterns from source IPs, or client-side telemetry. No detections created.

11. Recommended remediation, if any
No changes were made. If future lab work requires 4776 failure visibility, Credential Validation auditing would need to include Failure (policy change, not performed). If Kerberos failure visibility is needed, Kerberos Authentication Service auditing would need to include Failure (not performed). No recommendation to change production; this is an isolated lab.
